Set up before Session 2

Session 2 is hands-on. It assumes VS Code, Claude Code, and a project folder open on your laptop. Doing this beforehand saves the first half hour.

  1. Install VS Code and Claude Code. The Claude Code in VS Code guide walks through installation, the extensions worth having for Stata, Python, R, and LaTeX, and the first session. Claude Code needs a paid Claude plan (Pro, Max, Team, or Enterprise). Pro costs about $20 a month. On a free account, pair up with a neighbour for the exercises. Codex users can follow along too: the skills work there, and you type $ instead of / to run one.
  2. If your paper lives in Overleaf, link it to a folder on your computer so the agent can read it. Linking VS Code and Overleaf covers the GitHub and Dropbox routes.
  3. Install the skills below and restart VS Code.
  4. Bring one draft in LaTeX or markdown that you would like another pair of eyes on, preferably close to finished. The same paper works for the slide exercise. Also bring three or four PDFs of your own writing for the voice.md exercise. Leave out coauthored papers unless the introduction is yours.
  5. Open the whole project folder in VS Code (File, Open Folder), not a single file.
Nothing in a project folder is uploaded until you ask the agent to read it, but the agent does read what you point it at. Keep restricted data out of the folder. Session 2 covers how to work alongside secure servers.

Install the skills

A skill is a markdown file that Claude Code loads when you type its / command. My skills are in one public repository, github.com/claesbackman/AI-research-feedback (MIT licence). Fork them, edit them, make them yours. /voice-extractor is Mihail Velikov's and is in his repository. Copy its folder into the same place as the others. There are two ways to install.

Without a terminal

Windows Explorer or macOS Finder.

  1. Download the zip below and unzip it.
  2. Open the Skills folder inside. Copy each skill folder (review-paper, review-paper-checks, explorable-deck, and so on) into ~/.claude/skills/.
  3. That is a hidden folder in your user folder: C:\Users\you\.claude\skills on Windows, /Users/you/.claude/skills on a Mac. To see hidden folders in Explorer: View → Show → Hidden items. In Finder: Cmd-Shift-. in your home folder.
  4. Restart VS Code. Type / in Claude Code and the skills appear.
Download all skills (zip)

With a terminal

macOS, Linux, or WSL. Paste this one line. Run it again later to update.

git clone --depth 1 https://github.com/claesbackman/AI-research-feedback.git /tmp/airf && mkdir -p ~/.claude/skills && cp -R /tmp/airf/Skills/. ~/.claude/skills/ && rm -rf /tmp/airf

A skill in ~/.claude/skills/ works in every project. One in project/.claude/skills/ works only in that project. The README has one-line installers for individual skills.

What each skill does

These are the skills used in Session 2, in the order they come up. The review skills run only when you type the command. Claude will not launch a multi-agent review on its own. Reports are saved to a reviews/ folder next to your draft, and each skill is plain markdown you can open and change.

CommandWhat it doesWhen to use it
/review-paper-checks Three agents check the mechanics: spelling and grammar, internal consistency and cross-references, and unsupported claims. It reports errors you can fix, not editorial judgment. Exercise 1. Any draft in LaTeX or markdown.
/review-paper Pre-submission referee report. Eight subagents run in parallel: spelling and style, internal consistency, unsupported claims and identification, mathematics, tables and figures, a referee assessment, a contribution advocate, and a contribution skeptic. Add a journal: /review-paper AER. A draft you are about to circulate or submit. Ten to fifteen minutes.
/review-grant Six-agent panel review of a grant proposal against a named funder: /review-grant ERC. Before submission.
/pdf-to-markdown Converts a PDF to markdown in chunks, so the agent can read it reliably. A codebook, or a draft you only have as a PDF.
/explorable-deck Builds a Quarto slide deck from a paper in the style of Nicky Case's explorable explanations: one idea per slide, titles that state the point, a running example, figures you step through live, and an appendix for questions. Adapted from Nityesh Agarwal's skill for explorable websites. Exercise 2. Leave out the review and full options in class. They run much longer and use far more of your plan's limit.
/explorable-beamer The same kind of deck in LaTeX Beamer, compiled to PDF. If you work in LaTeX.
/explorable-pptx The same kind of deck as a PowerPoint file, with speaker notes on every slide. If you or your coauthors edit in PowerPoint.
/voice-extractor Reads a folder of your own papers and writes a voice.md: phrasing, sentence rhythm, hedging style, and a ban list. Written by Mihail Velikov. You can download it here. Exercise 3. Once per author.
/review-paper-code Maps the paper's empirical claims to the code that produces them. Checks reproducibility, sample restrictions, clustering, and fixed effects. Before a replication package leaves your hands. Shown as a demo in Session 2.

Exercises

The instructions from the Session 2 slides, so you can follow them without switching windows.

1. A referee report on your own draft · 10 min

  1. Open the folder with your draft in VS Code and start Claude Code.
  2. Type /review-paper-checks. The draft needs to be LaTeX or markdown. If you only have a PDF, run /pdf-to-markdown draft.pdf first.
  3. Click Allow when it asks to read files or run commands, then let it run.
  4. Other options: /review-paper for a longer review that includes an AI evaluation of the contribution, or /review-grant for a grant proposal. With no skill at all, type Read the paper in this folder and review it as a referee for [journal]: identification, unsupported claims, tables.

Then check the report (2 min). When the report is in, type in the same conversation: Launch a subagent to critique this report as a hostile referee. Report, do not fix. The agent that wrote the report will defend it. A fresh subagent will not.

Debrief. What did the report catch that you would not have seen? What did it get wrong? What did the adversary find that the report missed or overstated?

2. An explorable slide deck for a paper · 10 min

  1. In the folder with your paper, type /explorable-deck. Leave out the review and full options today.
  2. Click Allow when it asks to read files or run commands, then let it run.
  3. Prefer LaTeX? Use /explorable-beamer. Want PowerPoint? Use /explorable-pptx.

Two caveats. The deck is built from the paper, so a muddled paper gives a fluent deck about the wrong thing. And you need to practise more than before, because making the slides by hand was how you learned your own talk.

3. A voice.md from your own writing · 15 min

  1. Inside the project folder, make a folder sample-papers with three or four PDFs of your own writing. For coauthored papers, pick the ones where the introduction is yours.
  2. Type /voice-extractor sample-papers. Without the skill, type Read the PDFs in sample-papers and write voice.md: how I build paragraphs, sentence length, words I use and avoid, with quoted examples.
  3. Read voice.md and delete or edit anything that does not sound like you.
  4. Add one line to CLAUDE.md: “When editing my prose, match the voice in voice.md.” No CLAUDE.md yet? Type /init first.

Debrief. Which sentence in voice.md did you delete first? Did it name a habit you did not know you had?

Working with secure data

Not an exercise, but worth setting up before you next work on a secure server. Keep two files on your laptop: the codebook converted to markdown with /pdf-to-markdown, and a simulated dataset with the same variable names, types, and ranges as the real one. The agent writes and tests the code against these, and you carry the do-file across to the server by hand. Synthetic data tests that the code runs. It does not test that the results are right.

Does the code do what the paper says?

Shown as a demo in Session 2. In a project folder with a LaTeX paper and Stata, R, or Python code, type /review-paper-code. The report in reviews/ maps each claim in the paper to the script that produces it. Verify each finding before you act on it.

A CLAUDE.md starter template

CLAUDE.md sits in the project folder and is loaded at the start of every session. Type /init in Claude Code to have it drafted from the folder, or start from this and edit. Keep it to a page. Long workflows belong in skills. 

# About me
I am a researcher in [field].

# How I want you to work with me
- Ask clarifying questions before generating long output.
- Critical, skeptical tone in feedback. Do not flatter.
- When editing, preserve my voice (see voice.md). No generic LLM phrasing.
- Avoid bullet lists and passive voice in formal writing.
- Cite the specific line or section you are commenting on.

# Things to avoid
- Do not fabricate citations.
- Do not over-claim causality.
- Do not insert emoji or markdown decorations in formal docs.
