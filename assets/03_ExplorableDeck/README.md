# One Advisor for the Whole World? — conference deck

A Quarto reveal.js deck for *One Advisor for the Whole World? Cross-Country Evidence on
Financial Advice from Large Language Models* (`Writing/1_AI_FinAdvice.tex`, as revised
28 September 2026). Sixteen counted slides for a 20-minute slot, plus thirteen appendix
rooms for questions. Open `index.html` in a browser; no server is needed. The network is
needed only for the web fonts (Bricolage Grotesque, Newsreader, IBM Plex Mono, Noto Sans JP),
with system fallbacks otherwise.

```
index.qmd                 the deck, with speaker notes in every ::: {.notes} block
plan.md                   the talk script the deck was built from
build_data.py             gathers every charted number into js/data.js
theme/deck.scss           tokens, faces, layouts, stages, chat bubbles, lineup table
theme/fonts.html          the Google Fonts link
js/data.js                GENERATED by build_data.py; do not edit by hand
js/lib.js                 drawing helpers; exposes js/data.js as L.DATA
js/deck-charts.js         the stages, drawn at run time
js/include.html           the script tags Quarto appends to the body
shoot_chrome.py           screenshots every slide with the installed Chrome
shoot.py                  the same with playwright, plus an overflow check
_shots/                   screenshot output (gitignored)
```

## Rendering and checking

```sh
cd Presentation/03_ExplorableDeck
python build_data.py           # after any re-run of the Stata pipeline
quarto render index.qmd        # index.html + index_files/
python shoot_chrome.py         # _shots/NN.png for every slide, prints console messages
```

Keys while presenting: **S** speaker view (notes and timer), **F** fullscreen, **O**
overview, **E** print view, then print to PDF at 1280×720, landscape, no margins. `?static`
on the URL draws the two build-ins finished. For a single emailable file:
`quarto render index.qmd -M embed-resources:true`.

## Where the numbers come from

Every number a chart draws is read from `js/data.js`, which `build_data.py` writes from
the pipeline's tables of record in `output/tables/` (the same CSVs that
`10_paper_exhibits.do` and `04_benchmark_comparison.do` render into `Writing/Tables/`),
`output/analysis_data/gps_data.csv`, and the response histograms and country-by-model cell
means that `docs/explorable/extract_data.py` generated from the collection. Prose numbers
that also appear in a chart are `[ ]{.data key="..."}` spans that read the same object, so
the prose and the chart cannot disagree. A few prose numbers are transcribed from
`Writing/2_main.tex` because the pipeline writes them only to a log (the joint F-test, the
September tracking shares among new models, the judge-validation kappas); grep `index.qmd`
for the old value when the paper changes.

Headless Chrome freezes CSS transitions under `--virtual-time-budget`, so a scripted test
of a switch can show it off while the chart has moved. In a real browser it animates.

The two quoted answers on slide 08 are real responses from the main collection (Gemini 3
Flash, Question 1, Version B, age 40, repetitions 49 and 10), copied from the raw
`pilot_results.csv` backup. The English line under the Japanese answer is a close
translation and says so on the slide. Emily and Yuki are fictional; every number attached
to them is the United States or Japan cell.

## Conventions

- Four colours carry the argument, aliased in `theme/deck.scss`: **advice** = primary
  `#C4452A` (what a model recommends), **theory** = contrast `#1B6E7E` (what a benchmark
  prescribes), **emily** = actor-a `#B8760A` (the United States), **yuki** = actor-b
  `#6B4FA8` (Japan). Hatching marks the words of an answer, solid marks its number. Grey is
  everything else.
- The motif is the 60/40 split bar: under the title, under both 60% answers on the closing
  slide, and fanned out once per model on the appendix divider.
- The title slide carries the portfolio question in all 15 prompt languages (English amber,
  Japanese violet), read from `output/translations/translations.json` by `build_data.py`.
- Chat grammar: a prompt is the investor speaking (filled in the investor's colour, tail
  right), a reply is the model speaking (paper, tail left). Emily and Yuki appear as lettered
  discs, in the charts too, where a ring means the estimate does not survive Holm.
- Titles are assertions; read in sequence they are the talk.
- Appendix slides are `visibility="uncounted"`; each carries a link back to the slide that
  raises its question.
- Headings inside slides are `[Text]{.colhead}` or `[Text]{.ph}` spans, never `###`.
- References are hand-set in AER style on the last slide.
