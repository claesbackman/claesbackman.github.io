DTechnical Appendix: Prompts, Models, Translation, and Collection

This appendix reproduces the prompts, lists the dated version of every AI model used to create or classify the data, and documents the translation, collection, and parsing steps. The replication package contains the pipeline code, the assembled prompt for every country, version, question, and age, and the translation review and provenance records.

D.1Prompt structure and prompt texts

Each prompt consists of two blocks. The Instructions block specifies the JSON schema and is in English for every country and version. The Question block contains the investor’s stated demographics, the financial question, and the word limit on the explanation, and it is the only part of the prompt that varies across versions. An English Instructions block keeps JSON parsing rates near-identical across languages and removes a confound between the language treatment and response-format compliance. Each query is a single user message with no system prompt. The message consists of the Instructions block for the question, a blank line, and the Question block. The placeholder {age} is replaced by 30, 40, or 55 at query time. This section reproduces the English prompts verbatim.

Instructions blocks.

The Instructions block is in English for every country and version. The three blocks differ only in the JSON schema.

Question 1:

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
"fraction": float,  // fraction to invest in the stock fund, between 0 and 1
"explanation": string
}

Question 2:

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
"fraction_invest": float,  // fraction to invest in the stock fund (versus paying down the mortgage), between 0 and 1
"explanation": string
}

Question 3:

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
"fraction_to_invest": float,  // fraction of savings to move into investments, 0 to 1
"primary_instrument": string,  // main instrument recommended (e.g., "stock index fund", "inflation-linked bonds", "real estate", "gold")
"explanation": string
}

Question blocks, Version B (United States).

The Version B blocks for the other twenty countries replace the amount and the country name, and the fifteen local-language countries receive the translated block. Version B-cross uses the English text below with the local-currency amount and the country name of the corresponding Version B block.

Question 1:

I am {age} years old and looking to invest $50,000 over a five-year horizon. I have a standard pension plan otherwise. I live in the United States.

I am thinking of splitting my investment between a broad stock market index fund and some government bonds. What percentage should I invest in the stock fund?

Limit your explanation to a maximum of 200 words.

Question 2:

I am {age} years old with $50,000 in savings. I have a mortgage on my home with a 4% annual interest rate and 20 years remaining. I live in the United States. I am thinking about whether to use some or all of this money to pay down the mortgage, or to invest it in a broad stock market index fund instead.

What fraction of the $50,000 would you recommend I invest in the stock fund (versus using it to pay down the mortgage)?

Limit your explanation to a maximum of 200 words.

Question 3:

I am {age} years old with $50,000 sitting in a savings account earning 1% interest per year. Annual inflation is currently around 3%, meaning my savings are losing real value. I have a standard pension plan otherwise. I live in the United States.

What would you recommend I do to protect the real value of my savings?

Limit your explanation to a maximum of 200 words.

Question blocks, Version C (United States).

Version C replaces the generic instrument and pension vocabulary with the country-specific terms listed in Table A17. Question 1 reads as follows. Questions 2 and 3 make the same substitutions in the Version B text. Question 2 has no pension sentence, so only the equity instrument changes. Question 3 names no instrument, so only the pension reference changes.

Question 1:

I am {age} years old and looking to invest $50,000 over a five-year horizon. I have a standard 401(k) through my employer otherwise. I live in the United States.

I am thinking of splitting my investment between a broad US stock market index fund (such as a Vanguard or Fidelity total-market fund) and US Treasury bonds. What percentage should I invest in the stock fund?

Limit your explanation to a maximum of 200 words.

Stated-investor arm (Version B\(\gamma\rho\tau\)).

The stated-investor arm uses the English Version B text of Question 1 at age 40 for all twenty-one countries. The four risk-and-pension cells insert one risk statement and one pension statement after the country sentence. The two horizon cells insert no statement and replace “five-year” with “one-year” or “twenty-year.” The three exploratory balance-sheet probes each insert a single statement in the same position. Sections 6 and 6.3 quote the risk, pension, pension-composition, and hedging statements verbatim. The three wealth statements read as follows.

This amount is essentially all of my liquid wealth, and I hold little else in cash or savings for everyday needs and emergencies.

This amount is about half of my liquid wealth, and I hold roughly the same again in cash and other safe savings.

This amount is about a third of my liquid wealth, and I hold roughly twice as much in cash and other safe savings.

Exploratory re-collections.

The elicitation probe of Section 5.6 keeps the English Question 1 block at age 40 and replaces the Instructions block with the text below. The translated-Instructions arm replaces the English Instructions block of Question 1 with a DeepL translation into the prompt language, accessed October 29, 2026, with the JSON schema lines left unchanged.

Instructions:
A person has sent you the message below asking for investment advice. Before
giving a recommendation, you may ask them questions. List the questions you
would most want answered, in order of importance (at most 5). For each, say
briefly why it matters and how the answer would move your recommended share
in the stock fund. Then give the provisional share you would recommend if the
person answered nothing further.
Return the result as a JSON object with the following schema:
{
    "questions": [
        {
            "question": string,          // the question you would ask
            "why": string,               // why the answer matters, one sentence
            "direction": string          // "higher", "lower", "either", or "none": how the stock share would move
        }
    ],
    "provisional_fraction": float,       // share in the stock fund, between 0 and 1, if no further information
    "explanation": string                // at most 200 words
}

Judge rubric for the explanation coding.

Each judge receives a single user message that contains the rubric below followed by the explanation text. The judge sees no other part of the response and no information on the country, the model, or the allocation. The rubric was frozen at pre-registration.

You are coding a short financial-advice explanation written in any language.
Decide, for each category below, whether the explanation INVOKES that line of
reasoning. Code 1 if present, 0 if absent. Judge the reasoning itself, not the
quality of the advice. Do not infer anything not stated in the text.

Categories:
- infl: mentions inflation, loss of real value, or purchasing power as a reason.
- pens: refers to an existing pension, retirement plan, or social-security
  entitlement as background coverage the investor already has.
- horiz: reasons explicitly about the investment time horizon or how long the
  money will be invested (e.g. a five-year horizon, short vs. long term).
- local: refers to country-specific or local financial context — a named local
  instrument or broker, the local tax system, or the local pension/market.

Return ONLY a JSON object with integer 0/1 values and no other text:
{"infl": 0, "pens": 0, "horiz": 0, "local": 0}

D.4Translation and quality control

I produced the Version B and Version C Question blocks with the DeepL API on June 11, 2026. Version B-cross is the original English prompt and required no translation. The pipeline translates only the Question block, protects the pinned financial terms and the locked currency amounts so that they survive translation verbatim, and requests the formal register where the target language supports it. A provenance log stores every translation call with its raw response. The age-30, age-40, and age-55 prompts within a cell differ only in the stated age.

Two automated checks screened the machine output. A term-protection check verifies that every protected term and amount appears verbatim in the translated block. It caught three systematic failures, in which the translator dropped a currency amount, rendered an amount as the name of a financial product, or dropped a pension term. A back-translation of every block to English, scored with smoothed sentence BLEU against the source at a threshold of 0.6, routed blocks to human review. I did not use the score to accept translations, because it flags faithful translations into Japanese, Korean, and Chinese and it passed at least one wrong translation.

The acceptance gate was native-speaker review of the Version B and Version C blocks in all fifteen translated countries and of the local-instrument wording for India. I reviewed the Swedish blocks myself as a native speaker. South Africa had no available native reviewer. I verified its blocks with a two-model cross-check instead, using Gemini 3.1 Pro (google/gemini-3.1-pro-preview) and GPT-5.5 (openai/gpt-5.5) at temperature zero between June 29 and July 1, 2026, with a pre-stated escalation rule. The cross-check surfaced one instrument-naming error, which I corrected and re-verified on both models. I ran the same cross-check on the United Kingdom, Australia, and Canada blocks and re-ran it on Mexico and Spain after their native reviews. I adopted a model suggestion only where it did not contradict a native reviewer’s decision. Before I filed the pre-registration, every assembled prompt passed a deterministic consistency audit with zero failures, a Claude Opus model reviewed all ninety unique translated blocks adversarially, and I read every block in full. I then froze the translations for collection.

D.5Collection and parsing

The runner submits each query to the OpenRouter API as a single user message with temperature 0.7 and a 4,000-token cap, and it sets no other sampling parameter. It submits the queries in random order. The runner logs each parsed response before the raw API response and skips completed queries on restart, so an interruption cannot produce a duplicate observation. The main run covered the design grid exactly, with fifty repetitions in every cell, no duplicates, and no unresolved API errors.

Parsing proceeds in a fixed order of decreasing strictness. The parser first extracts the first balanced brace block in the response and attempts to read it as JSON against the schema stated in the Instructions block. A JSON value between 1 and 100 is read as a percentage and divided by 100. If the JSON step fails, the parser searches for a decimal fraction, and then for a percentage, in each case only where the number appears in explicit allocation language, so that a stray number elsewhere in the response cannot be mistaken for a recommendation. Of the 267,150 responses, the parser read 266,798 as JSON, rescaled 2 JSON values, recovered 113 through the two fallback searches, and failed on 237. A parse-method field records the strategy for each observation, which allows any analysis to be re-run on the strictly JSON-parsed subsample. Responses whose generation stopped at the 4,000-token ceiling are marked truncated and excluded under the pre-registered rule.

Refusal detection runs after parsing. A response is classified as a refusal only when a refusal phrase matches and no numeric recommendation was parsed, which prevents advisory boilerplate such as “consult a financial advisor” on an otherwise valid answer from being misclassified. The phrase list covers all fourteen prompt languages (thirteen non-English languages plus English, with Swiss German and Mexican Spanish handled as within-language variants). The main collection produced no refusals.

Every row records both the requested and the returned model identifier (Table A19). In the main collection each requested identifier resolved to a single dated version throughout, so no model changed versions mid-run.
