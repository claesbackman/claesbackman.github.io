ATechnical Appendix: Prompts, Models, Translation, and Collection

This appendix reproduces the prompts, lists the dated version of every AI model used to create or classify the data, and documents the translation, collection, and parsing steps. The replication package contains the pipeline code, the assembled prompt for every country, version, question, and age, the translation review and provenance records, and the logs of the model-based translation checks.

A.1Prompt structure and prompt texts

Each prompt consists of two blocks. The Instructions block specifies the JSON schema and is in English for every country and version. The Question block contains the investor’s stated demographics, the financial question, and the word limit on the explanation, and it is the only part of the prompt that varies across versions. An English Instructions block keeps JSON parsing rates near-identical across languages. An exploratory re-collection of the primary cell with the Instructions block translated leaves the country contrasts intact, with a correlation of 0.93 with the main estimates (Section 5.6). Each query is a single user message with no system prompt. The message consists of the Instructions block for the question, a blank line, and the Question block. The placeholder {age} is replaced by 30, 40, or 55 at query time. This section reproduces the English prompts verbatim.

Instructions blocks.

The Instructions block is in English for every country and version. The three blocks differ only in the JSON schema.

Question 1:

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
"fraction": float,  // fraction to invest in the stock fund, between 0 and 1
"explanation": string
}

Question 2:

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
"fraction_invest": float,  // fraction to invest in the stock fund (versus paying down the mortgage), between 0 and 1
"explanation": string
}

Question 3:

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
"fraction_to_invest": float,  // fraction of savings to move into investments, 0 to 1
"primary_instrument": string,  // main instrument recommended (e.g., "stock index fund", "inflation-linked bonds", "real estate", "gold")
"explanation": string
}

Question blocks, Version B (United States).

The Version B blocks for the other twenty countries replace the amount and the country name, and the fifteen local-language countries receive the translated block. Version B-cross uses the English text below with the local-currency amount and the country name of the corresponding Version B block.

Question 1:

I am {age} years old and looking to invest $50,000 over a five-year horizon. I have a standard pension plan otherwise. I live in the United States.

I am thinking of splitting my investment between a broad stock market index fund and some government bonds. What percentage should I invest in the stock fund?

Limit your explanation to a maximum of 200 words.

Question 2:

I am {age} years old with $50,000 in savings. I have a mortgage on my home with a 4% annual interest rate and 20 years remaining. I live in the United States. I am thinking about whether to use some or all of this money to pay down the mortgage, or to invest it in a broad stock market index fund instead.

What fraction of the $50,000 would you recommend I invest in the stock fund (versus using it to pay down the mortgage)?

Limit your explanation to a maximum of 200 words.

Question 3:

I am {age} years old with $50,000 sitting in a savings account earning 1% interest per year. Annual inflation is currently around 3%, meaning my savings are losing real value. I have a standard pension plan otherwise. I live in the United States.

What would you recommend I do to protect the real value of my savings?

Limit your explanation to a maximum of 200 words.

Question blocks, Version C (United States).

Version C replaces the generic instrument and pension vocabulary with the country-specific terms listed in Table A1. Question 1 reads as follows. Questions 2 and 3 make the same substitutions in the Version B text. Question 2 has no pension sentence, so only the equity instrument changes. Question 3 names no instrument, so only the pension reference changes.

Question 1:

I am {age} years old and looking to invest $50,000 over a five-year horizon. I have a standard 401(k) through my employer otherwise. I live in the United States.

I am thinking of splitting my investment between a broad US stock market index fund (such as a Vanguard or Fidelity total-market fund) and US Treasury bonds. What percentage should I invest in the stock fund?

Limit your explanation to a maximum of 200 words.

Stated-investor arm (Version B\(\gamma\rho\tau\)).

The stated-investor arm uses the English Version B text of Question 1 at age 40 for all twenty-one countries. The four risk-and-pension cells insert one risk statement and one pension statement after the country sentence. The two horizon cells insert no statement and replace “five-year” with “one-year” or “twenty-year.” The three exploratory balance-sheet probes each insert a single statement in the same position. Sections 6 and 6.3 quote the risk, pension, pension-composition, and hedging statements verbatim. The three wealth statements read as follows.

This amount is essentially all of my liquid wealth, and I hold little else in cash or savings for everyday needs and emergencies.

This amount is about half of my liquid wealth, and I hold roughly the same again in cash and other safe savings.

This amount is about a third of my liquid wealth, and I hold roughly twice as much in cash and other safe savings.

Exploratory re-collections.

The elicitation probe of Section 5.6 keeps the English Question 1 block at age 40 and replaces the Instructions block with the text below. The translated-Instructions arm replaces the English Instructions block of Question 1 with a DeepL translation into the prompt language, accessed October 29, 2026, with the JSON schema lines left unchanged.

Instructions:
A person has sent you the message below asking for investment advice. Before
giving a recommendation, you may ask them questions. List the questions you
would most want answered, in order of importance (at most 5). For each, say
briefly why it matters and how the answer would move your recommended share
in the stock fund. Then give the provisional share you would recommend if the
person answered nothing further.
Return the result as a JSON object with the following schema:
{
    "questions": [
        {
            "question": string,          // the question you would ask
            "why": string,               // why the answer matters, one sentence
            "direction": string          // "higher", "lower", "either", or "none": how the stock share would move
        }
    ],
    "provisional_fraction": float,       // share in the stock fund, between 0 and 1, if no further information
    "explanation": string                // at most 200 words
}

The mortgage question without the stated rate.

The no-rate arm of Section 5.4 uses the English Question 2 block at age 40, Version B in the six English-prompting countries and B-cross in the other fifteen, with one deletion. The sentence “I have a mortgage on my home with a 4% annual interest rate and 20 years remaining.” becomes “I have a mortgage on my home with 20 years remaining.” The stake, the country sentence, the question, and the word limit are unchanged. The Instructions block is the Question 2 block with two fields added after the recommendation and before the explanation, so that the model states its advice before its assumptions. The comments give no example values, to avoid anchoring the assumed rates.

Instructions:
Consider the following question and respond according to the template provided.
Return the result as a JSON object with the following schema:
{
    "fraction_invest": float,   // fraction to invest in the stock fund (versus paying down the mortgage), between 0 and 1
    "assumed_mortgage_rate": float,   // annual mortgage interest rate you assumed, as a decimal
    "assumed_inflation_rate": float,   // annual inflation rate you assumed, as a decimal
    "explanation": string
}

A field check asks the same question with the unchanged Question 2 Instructions block, without the two assumption fields, in the United States, Turkey, Brazil, Japan, and Germany at ten repetitions per model.

Judge rubric for the explanation coding.

Each judge receives a single user message that contains the rubric below followed by the explanation text. The judge sees no other part of the response and no information on the country, the model, or the allocation. The rubric was frozen at pre-registration.

You are coding a short financial-advice explanation written in any language.
Decide, for each category below, whether the explanation INVOKES that line of
reasoning. Code 1 if present, 0 if absent. Judge the reasoning itself, not the
quality of the advice. Do not infer anything not stated in the text.

Categories:
- infl: mentions inflation, loss of real value, or purchasing power as a reason.
- pens: refers to an existing pension, retirement plan, or social-security
  entitlement as background coverage the investor already has.
- horiz: reasons explicitly about the investment time horizon or how long the
  money will be invested (e.g. a five-year horizon, short vs. long term).
- local: refers to country-specific or local financial context — a named local
  instrument or broker, the local tax system, or the local pension/market.

Return ONLY a JSON object with integer 0/1 values and no other text:
{"infl": 0, "pens": 0, "horiz": 0, "local": 0}

A.2Country panel and query accounting

Table A1 lists the prompt language, the investment amount, and the Version C vocabulary for each country. Table A2 gives the number of queries by arm. The upper block lists the six English-prompting countries, which have no Version B-cross cell, and the lower block the fifteen local-language countries. The investment amount is the round local-currency equivalent of $50,000, identical across Versions B, C, and B-cross within a country, and rendered in the prompt in the native number format (e.g. “500 000 kr” in Sweden, “45.000 Euro” in Germany). The three context columns give the country-specific vocabulary that Version C substitutes for the generic Version B wording (“a broad stock market index fund,” “government bonds,” “a standard pension plan”), condensed from the exact prompt sentences. In most countries the Version C equity instrument is a global or MSCI World-type tracker. India is the exception, naming a domestic Nifty index fund, so for India the Version C step also shifts the underlying equity exposure and not only its label. Pension terms that appear in Japanese, Korean, or Chinese script in the prompts are shown here in romanized form.

A.4Translation and quality control

I produced the Version B and Version C Question blocks with the DeepL API on June 11, 2026. Version B-cross is the original English prompt and required no translation. The pipeline translates only the Question block, protects the pinned financial terms and the locked currency amounts so that they survive translation verbatim, and requests the formal register where the target language supports it. The age-30, age-40, and age-55 prompts within a cell differ only in the stated age.

Two automated checks screened the machine output. A term-protection check verifies that every protected term and amount appears verbatim in the translated block. It caught three systematic failures, a dropped currency amount, an amount rendered as a product name, and a dropped pension term. A back-translation of every block to English, scored with sentence BLEU, routed blocks to human review. I did not use the score to accept translations, because it flags faithful translations into Japanese, Korean, and Chinese.

The acceptance gate was native-speaker review of the Version B and Version C blocks in all fifteen translated countries and of the local-instrument wording for India. I reviewed the Swedish blocks myself. South Africa had no available native reviewer, so I verified its blocks, and those of the United Kingdom, Australia, and Canada, with a two-model cross-check (Table A3, Panel C). The cross-check found one error, in the South African Version C pension reference, which sat in the design table rather than in a translation. I corrected it through a dated design-lock amendment on June 29, 2026. The same two models audited the Version C blocks of the translated countries, and I adopted a model suggestion only where it did not contradict a native reviewer. Before I filed the pre-registration, every assembled prompt passed a deterministic consistency audit with zero failures, Claude Opus 4.8 reviewed all ninety unique translated blocks adversarially and found no error, and I read all ninety blocks in full. A Google Translate back-translation of a stratified sample of thirty-four blocks also passed. I then froze the translations for collection.

A.5Collection and parsing

The runner submits each query to the OpenRouter API as a single user message with temperature 0.7 and a 4,000-token cap, sets no other sampling parameter, and submits the queries in random order. OpenRouter drops any parameter a model endpoint does not support without an error. Its listing of supported parameters, accessed on 16 November 2026, includes temperature for no endpoint of GPT-5-mini, GPT-5.5 or Claude Opus 4.8, so these three models ran at their providers’ default sampling in every arm. The runner logs each parsed response before the raw API response and skips completed queries on restart. A restart on July 4 re-sent two queries, and the staging step keeps the first response to each, so the analysis file holds one observation per query and every cell has exactly fifty.

Parsing proceeds in a fixed order of decreasing strictness. The parser first reads the first balanced brace block in the response as JSON and takes the fraction field that the Instructions block names, and then tries the whole response as JSON. A JSON value above 1 and at most 100, or one stated with a percent sign, is read as a percentage. If both JSON steps fail, the parser searches for a decimal fraction and then for a percentage, in each case only next to explicit allocation language and not next to rate language such as the prompt’s interest and inflation rates. Of the 267,150 responses, 266,800 parsed as JSON (2 of them after rescaling a percentage), 113 parsed through the fallback searches, and 237 failed. A parse-method field records the strategy for each observation, so any analysis can be re-run on the strictly JSON-parsed subsample.

The pre-registered truncation rule excludes the 137 responses that stopped at the token ceiling, 130 of which also failed to parse. Together with the other 107 parse failures, this leaves 266,906 responses for analysis. The failures concentrate by model and not by country. DeepSeek V4 Pro accounts for 133 of the 237 and Gemini 3.1 Pro for 47, while no country has more than 22. Twenty-four responses with an error finish reason parsed and stay in the sample, because the pre-registered rules exclude only unparsed and truncated responses.

A response counts as a refusal only when a refusal phrase matches and no numeric recommendation was parsed, so that boilerplate such as “consult a financial advisor” on a valid answer is not misclassified. The phrase list covers all fourteen prompt languages, and the main collection produced no refusals. Every row records both the requested and the returned model identifier. Each requested identifier resolved to a single dated version throughout the main collection (Table A3), and the eleven responses without a returned identifier all failed to parse.

The no-rate arm.

The arm of Section 5.4 was collected on November 16 and 17, 2026 with the same runner, temperature, token cap, and parser as the main collection, after a smoke test of 390 queries in three countries that is not part of the data. It comprises 6,825 queries without the rate (twenty-one countries, thirteen models, twenty-five repetitions) and 650 field-check queries (five countries, ten repetitions). Twelve responses stopped at the token ceiling and three failed to parse, which leaves 6,812 and 648 responses for analysis. No response was a refusal. The two assumed rates parse from the JSON object in 6,815 and 6,814 of the 6,825 no-rate responses. A value above one would be read as a percentage, but every model reported the rates as decimals. In November the API returned only the requested identifier for every model, not a dated version, so the versions in Table A3 cannot be confirmed for this arm. The numbered comparison cell is the English Question 2 cell of the main collection (13,629 responses after the same exclusions).
