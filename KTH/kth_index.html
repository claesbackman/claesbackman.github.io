Set up before Session 2

Session 2 assumes VS Code, Claude Code, and a project folder with the files below. Setting this up before the afternoon starts saves the first fifteen minutes.

  1. Install VS Code and Claude Code. The Claude Code in VS Code guide walks through installation, the extensions worth having, and the first session. Claude Code needs a paid Claude plan (Pro, Max, Team, or Enterprise). Without one, Copilot Chat works for exercises 1, 3, 4, and 5: upload the files and paste the prompt. Exercise 2 needs an agent that reads the folder, so pair up with a neighbour or use GitHub Copilot in VS Code.
  2. Open a project folder, not a single file. File → Open Folder. Put your syllabus, course memo, one week of lecture notes, and your thesis rubric in it. Word or PDF is fine.
  3. Download the morning's thesis and the example rubric into the same folder: paper.pdf and rubric.md. You can use your own rubric instead.
  4. Check that the panel answers. Type / in the Claude Code panel and a list of commands appears. @file points the agent at a file in the folder.
Student work stays out of AI tools. KTH's guidance is that personal data, student work, and exam answers never go into an AI tool, and that includes feedback. The exercises therefore use the thesis the agent wrote in Session 1, which is not student work.

Hands-on exercises

The exercise cards from the Session 2 slides, so you can follow them without switching windows. Each one is the same move: put the right files in the folder, type one prompt, and read what comes back as a draft to check, not an answer to accept.

Exercise 1 · 10 min

Feedback on a thesis

  1. Put paper.pdf and rubric.md in the folder, or your own rubric next to the thesis.
  2. Before you press Enter, write down two guesses: one problem the feedback will catch, and one it will miss.
  3. In the Claude Code panel, type:
    Read @paper.pdf and @rubric.md. For each criterion, give the evidence with section references and the one change that would most improve the thesis. Report, do not rewrite. Save the report as feedback-1.md.
  4. Click Allow if it asks to write the file.

In Copilot Chat. Upload paper.pdf and rubric.md, paste the prompt, and save the answer as feedback-1.md yourself. If nothing runs, a finished report is here: feedback-1.md.

Exercise 1b · 2 min, then debrief

A second opinion on the feedback

  1. When feedback-1.md is written, start a new conversation and type:
    Read @feedback-1.md and @paper.pdf. Critique the feedback as a hostile examiner. Report, do not fix.
  2. Read the report against your two guesses. What did it catch that you would not have seen? What did it get wrong?
  3. What did the adversary find that the report missed, or overstated?
  4. Which criterion would you read first next time, and why?

In Copilot Chat. Open a new chat, upload feedback-1.md and paper.pdf, and paste the prompt.

Exercise 1c · 5 min

Defence questions

  1. In a new conversation, type:
    Read the thesis in this folder. Write five questions for the opponent to ask at the defence, each answerable in under a minute without the text: one on the research question, one on the data, one on a specific table or figure, one on a choice the student made, and one on what the result does not show. For each, say what a good answer contains.
  2. Check that every question points at something that is really in the thesis. Delete the generic ones.

Debrief. Which question would you actually ask? Which one tests nothing?

Exercise 2 · 15 min

Turn your rubric into a skill

  1. Type:
    Make a skill called thesis-feedback in .claude/skills that does what my exercise 1 prompt did: read the thesis and rubric.md, give the evidence per criterion with section references, report without rewriting, and save the report as feedback.md.
  2. Open the SKILL.md it wrote and read it. You can change it yourself.
  3. Start a new conversation, type /thesis-feedback, and run it on the same thesis.
  4. Compare feedback.md with feedback-1.md. Edit SKILL.md once more for what it still gets wrong.

No agent? GitHub Copilot in VS Code reads .claude/skills too. In Copilot Chat, ask for the SKILL.md text, save it yourself, and paste it as the first message of a new chat with the thesis.

Debrief. Which instruction did you change first? Would you give this skill to your students?

Exercise 3 · 5 min

An AI policy

  1. Put your course memo in the folder: Word, PDF, or markdown. No memo? Use the syllabus.
  2. Type:
    From the course memo and the thesis schedule, draft an AI policy for the course: what students may use AI for, what they must disclose and how, and which parts the defence will test without the text. Write in plain language, for students.
  3. Read, verify, and edit the draft, and tell the agent what you want changed.

Debrief. What did it allow that you would not?

Exercise 4 · 10 min

A quiz bank from your notes

  1. Put one week's lecture notes in a notes/ folder. Markdown, LaTeX, or PDF all work. A .pptx? Ask the agent to convert it first.
  2. Guess first: how many of the 15 answer keys will be wrong? Then type:
    From the notes in notes/, write 15 multiple-choice questions at three levels, with distractors built from common misconceptions and a one-sentence explanation each.
  3. Read every question. Verify every answer key yourself.

Exercise 5 · optional · 10 min

A course update

  1. Put the syllabus, the course memo, and the list of lectures in the folder. If KTH or your department has guidance on sustainability or gender equality in teaching, add it.
  2. Type:
    From the syllabus, the course memo and the guidance in this folder, propose where a sustainability or gender perspective fits in this course: one concrete example per week, each tied to an existing learning outcome, with a reading or dataset I can check. Do not change any files.
  3. Check that every reading exists. Or start from last year's course analysis: list the three changes students asked for most, and propose how to make each.

Your own task · 20 min

One thing from the morning, on your own material

Update a lecture so that slides with 2015 examples get current ones. Write a rubric from the course's learning outcomes and test it on the morning's thesis. Build a data exercise from a public source such as SCB, ECB, Eurostat, or the World Bank. Draft next year's course memo from last year's memo, the new template, and this year's dates. Turn the criterion students miss most often into a skill they can run on their own draft. Write problem sets with solutions at three levels, with a rubric, and check every key yourself.

A CLAUDE.md starter template

CLAUDE.md sits in the project folder and is loaded at the start of every session. Type /init in Claude Code to have it drafted from the folder, or start from this and edit. 

# About me
I am a researcher in [field].

# How I want you to work with me
- Ask clarifying questions before generating long output.
- Critical, skeptical tone in feedback. Do not flatter.
- When editing, preserve my voice (see voice.md). No generic LLM phrasing.
- Avoid bullet lists and passive voice in formal writing.
- Cite the specific line or section you are commenting on.

# Things to avoid
- Do not fabricate citations.
- Do not over-claim causality.
- Do not insert emoji or markdown decorations in formal docs.
